# Threadnote Personal Cursor Cloud

Use the installed `threadnote-context` and `threadnote-memory` skills for non-trivial work.
This Cloud Agent has one Threadnote MCP bounded to the configured personal Git memory shares. Repository files and the
nearest checked-in agent guidance remain authoritative. Read recalled `threadnote://` pointers before relying on them,
and store a concise closeout. Never store secrets, credentials,
customer data, or raw production logs.

Use the installed dev-spec → dev-plan → dev-cycle workflows for specification, reviewed planning and implementation; watch-pr supplies PR monitoring and repair. Bootstrap installs these by default; --no-dev-skills persists opt-out on supported native platforms. Startup maintains only recorded enabled ownership. Missing enrollment requires explicit bootstrap/setup; never infer consent from cached files. Private workflow artifacts are task-local and can disappear with the environment; durable closeout requires an explicitly approved projection to the configured personal Git share.

At personal task startup, enter the checkout and run `threadnote cloud cursor start --cwd "$PWD"` to restore enabled managed files, synchronize the configured personal share and verify readiness. A separate cloud image/runtime must update itself; a local runtime update cannot update that environment.
