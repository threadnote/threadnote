# Plan review

Give the reviewer the bounded plan packet, current code evidence, and approved spec. Ask for evidence-based challenge, not affirmation.

Check traceability from requirements to phases, current/target architecture separation, source anchors, scope and exclusions, dependencies, acceptance and practical verification, compatibility, and whether material alternatives were considered. Flag vague phases or invented current components.

Resolve material findings and refresh evidence after source changes. Review cannot approve intent for the user, prove implementation works, or authorize publication. Record the result for the exact plan digest.
