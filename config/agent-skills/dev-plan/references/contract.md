# Plan quality bar

Use the native authoring schema for exact fields and the native validator for current structural and evidence rules.

- Preserve approved spec identity, requirements, scenario IDs, constraints, decisions, and exclusions.
- Show current and target architecture separately. Ground current architecture in inspected code; label proposed components as proposals, not existing graph symbols.
- Define phases as working slices with outcomes, source scope, dependencies, acceptance, and checks that can actually be run. Map all approved scenarios; do not weaken or omit criteria.
- Keep routine implementation choices open. Preserve considered alternatives and rationale in durable plan content. For a bounded high-level design challenge, present no more than two material options with evidence and tradeoffs; let the orchestrator judge against approved intent.
- Cite relevant code and pinned memories. Refresh evidence when the source changes; do not claim a graph is ready when it is partial or stale.

Read the complete rendered plan before approval. Confirmation and review apply to the exact plan digest. A semantic change invalidates approval; source-only evidence refresh does not. Save and independently read back a meaningful private draft before pausing. Export to a cycle only from the approved current plan.

Closeout uses the native source of truth and exact owned-artifact identities. It must preserve rationale and implemented architecture, verify final output readback, and retire only owned drafts after success. Personal cloud publication stays private until an exact preview is explicitly approved and publication is verified. Runtime receipts and CAS are authoritative; local files are not.
