# Independent specification review

Give a reviewer the bounded acceptance packet, relevant source, and pinned memory evidence. Ask for an evidence-based judgment of the actual artifact.

Check observable acceptance, contradictions, requirement coverage, consequential assumptions, permissions, failure states, domain identity and invariants, contract compatibility, scope, and whether cited evidence supports the claims. Diagrams should explain behavior without prematurely choosing architecture.

Record the reviewer outcome against the current packet digest. Resolve material findings before readiness; one targeted follow-up is enough after a material revision. Review is scrutiny, not user approval or proof that runtime behavior passes.
