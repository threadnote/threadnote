# Feature memory and publication

Before a substantive PR, refresh the durable feature memory with the complete rationale, considered alternatives, actual implementation, and current code evidence. Read the full result back and verify it against the source. Existing authorization to share persists; do not ask again when it already covers this action.

Keep memory private unless publication is authorized. For personal cloud, work remains task-local until a concrete publication preview receives explicit approval and native verification succeeds. Do not publish raw private planning records.

Update linked knowledge through native workflow actions. Preserve stable identities and history; retire only artifacts the current run owns, and only after independent final readback.
