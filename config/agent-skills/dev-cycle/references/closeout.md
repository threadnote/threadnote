# Cycle closeout

Use closeout only after the plan’s required phases, acceptance, and delivery receipts are complete. Refresh current source evidence and verify final combined-tree acceptance. Persist full rationale, actual implemented choices, and links to the approved plan/spec; read every output back independently.

Archive only exact draft artifacts owned by this run, after durable output verification. Keep unrelated artifacts and all drafts if any admission, approval, write, or readback step fails. Personal cloud closeout remains task-local until the exact publication preview is explicitly approved and verified.

Resume an interrupted closeout by its original run and transaction. Recover the recorded operation and confirm its exact result; do not generate new content or expected revisions to force a retry. The receipt is authoritative.

If a prepared admission becomes stale after a CI source repair or cycle invalidation, inspect it read-only first. Use `closeout recover` only when the original reservation and every lower operation, output, archive, publication journal and owned draft prove that no closeout effect began. Recovery fences the old admission before releasing its exact reservation. Readmission retains a non-executable `admitting` journal before reserving capacity; a failed reservation or final journal commit can be retried with the same proposal or safely recovered. Retry recovery after interruption; the fenced admission stays inspectable and cannot finish. Reaccept the affected phase against the new source through a fresh cycle review before preparing again. For changes to a merged phase's source, approve and review a new repair phase covering every changed path while preserving the merged history. A pristine aborted `admitting` readmission retains that fresh qualification only while its exact source and cycle runtime remain unchanged. Old background jobs remain bound to their admission through canonical dispatch.
