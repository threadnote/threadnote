# Dev Cycle

The orchestrator owns handoff memories. Background agents report results and artifact links directly; they do not store handoff memories. Include this boundary in delegated prompts.

At closeout, print a labeled list of the verified canonical `threadnote://` URIs for the stored spec and plan when present, plus every other memory created or updated during closeout. Show each full URI as a clickable link with its readiness and private/shared status where relevant. List only records that were successfully persisted and independently read back.

Resources: `{{THREADNOTE_SKILL_ROOT}}`; bundle: `{{THREADNOTE_BUNDLE_ROOT}}`. Use these pinned roots for linked files and generation identity. In an unrendered checkout, use this skill directory and its parent. Start with the [workflow bootstrap]({{THREADNOTE_BUNDLE_ROOT}}/dev-cycle/references/native-bootstrap.md).

Use workflow-automation JSON actions for cycle state, phase delivery, watch, and closeout. Retrieve only the current action schema from the installed runtime. Do not use legacy local scripts or invent fields. The runtime owns receipts, CAS, publication authority, durable dispositions, and acknowledgement rules.

When `capabilities.operations` includes `job`, use it for heavy supported authoring saves or closeout prepare/finish on clean committed source: discover the job command schema, submit exact canonical work once, retain `jobId`, and inspect `status`/`result`. `accepted` is durable admission; require `completed`, verified result and independent output readback before claiming a save or closeout. Cancel or resume with the same ID; use synchronous actions for unsupported or dirty source. Existing ready and publication guards still apply.

1. Start with `threadnote-context`, repository guidance, and a fresh current source graph. Read the plan root plus only the current and dependency phase evidence. Preserve approved requirements, exclusions, prior phase state, and delivery history. Use `threadnote-code-graph` for unfamiliar relationships or unresolved evidence gaps; use exact-path reads for known code.
2. Delegate implementation of each working, reviewable phase slice to the cheapest sufficient background agent. The orchestrator provides bounded, actionable guidance and coordinates work but does not implement source. Require implementation workers and their descendants to work quietly, returning concise results, artifact links, checks, and actionable blockers. For packet contents, model/effort selection, escalation, and quiet-worker guidance, read [delegation]({{THREADNOTE_SKILL_ROOT}}/references/delegation.md); read [implementation practice]({{THREADNOTE_SKILL_ROOT}}/references/implementation.md) for execution details. The orchestrator must never review the source or count itself as a reviewer, even when another agent implemented the change. Before delegating review, read the [review contract]({{THREADNOTE_SKILL_ROOT}}/references/review.md), assess every specialist trigger against the actual change, and record selected lanes and evidence-based reasons for skipped lanes. Always delegate independent `correctness` and `simplicity` reviews to distinct background agents, plus every applicable specialist lane; no reviewer may have implemented that slice. The base pair is sufficient only when no specialist trigger applies.
3. Validate the actual current tree and every acceptance obligation. Preserve assertions and evidence; never claim unrun checks. For substantive PR work, refresh the feature memory before publication and read back its full rationale and actual implementation, including if authorization to share was already granted.
4. Before creating a PR, recall user preferences and apply any PR-description style. For multiphase features in GitHub repositories, prefer stacked phase PRs. When authorized, deliver the phase, record its verified commit/PR receipt, and use [watch-pr]({{THREADNOTE_BUNDLE_ROOT}}/watch-pr/SKILL.md) to start or transfer the sole watch and its owning-chat wakeup. Continue the next eligible phase. If no eligible work or actionable event remains, end the model turn immediately; the watch owns the wait for CI, reviews, or merge readiness.
5. Follow watch-pr's setup and idle-handoff rules; do not substitute foreground or delegated model polling. Persist each event disposition before acknowledging its delivery. Acknowledgement never resolves work; preserve open or blocked work across acknowledgements. Leave the collector running between model turns. Stop it only at a terminal outcome or cancellation, after preserving pending work.
6. Finish with the closeout flow: current combined-source evidence, full rationale, implemented architecture, independent durable readback, and retirement of only owned drafts. Do not mark completion from a PR merge or CI signal alone. Personal cloud knowledge remains task-local until the user approves the exact publication and readback verifies it.

Use the linked references for [phases]({{THREADNOTE_SKILL_ROOT}}/references/phases.md), [review]({{THREADNOTE_SKILL_ROOT}}/references/review.md), [delivery]({{THREADNOTE_SKILL_ROOT}}/references/delivery.md), [watch handoff]({{THREADNOTE_BUNDLE_ROOT}}/watch-pr/SKILL.md), and [closeout]({{THREADNOTE_SKILL_ROOT}}/references/closeout.md). Follow host-required progress reporting, otherwise keep implementation quiet and return a concise evidence-based result.
