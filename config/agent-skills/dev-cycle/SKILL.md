# Dev Cycle

Start or resume with `workflow_task_start`, then follow `workflow_task_view` and its current card. For a bounded, clear, low-risk fix, use compact intent; expand when behavior is unresolved, phases depend on one another, or design risk is material. Registered MCP tools are `workflow_task_compact_start`, `workflow_task_compact_expand`, and `workflow_task_compact_confirm`; `workflow_task_author` handles standard spec/plan authoring. The CLI equivalents are under `threadnote workflow-automation`: `task-start`, `task-view`, `task-action`, `task-author`, and `watch-pr`. Check the relevant command's `--help` for current options. Provide business content and semantic judgments, never raw workflow-automation JSON or fabricated metadata.

When an admitted current plan can own a discovered workflow tooling fix, reconcile that fix into the plan instead of starting an auxiliary cycle solely for the repair; keep its source review, validation, and delivery gates.
Keep reasonable owned path coverage for review corrections. Routine fixes within approved requirements need a fresh source snapshot and review, not repeated business-plan rewrites; reconcile the plan when requirements or ownership actually change.
When a validated or published phase needs a routine correction, use its current task card reference with `workflow_task_control` `reopen`, an explicit phase ID, and the observed reason; then resume the stale phase and record fresh source, review, validation, and delivery. Reopening retains prior proof and does not rewrite a merged phase.

Use the current card's missing inputs and returned opaque references. `workflow_task_work` prepares bounded implementation packets; assign the cheapest sufficient background implementer and require quiet work, including descendants. The coordinator coordinates but never implements source or reviews it. Give workers objective, acceptance, owned paths, constraints, necessary dependency context, and evidence. Escalate only on concrete evidence.

Once an authorized PR watch is established, routine CI, review, and conflict maintenance uses the approved plan and existing watch, with focused checks, distinct independent reviews, normal commits/pushes, and exact current Git/CI evidence. This is an exception to the native phase-card, reopening, reconciliation, snapshot, review/validation recording, redelivery, and replanning requirements here; historical references do not validate the new head. Preserve exact watch notice ownership, disposition before ACK, and current-head merge guards. Verify the actual PR base before a normal conflict merge; an unchanged approved base binding needs no new plan. Initial admission/delivery and new scope or changed user intent retain normal routing and source guards. For changed source, require distinct independent correctness and simplicity reviews plus every risk-triggered security, architecture, performance, flaky-test, quality, or DevEx review. Assess each lane and record evidence-based skip reasons; no quota and no self-review. Quality applies when verification strategy, oracle design, difficult failure coverage, or a meaningful property is at risk, not for every behavior change; rerunning an adequate, unchanged oracle alone does not trigger it. Outside established-watch maintenance, review the current immutable snapshot and use `workflow_task_snapshot` for recording; supersede only an eligible unreviewed predecessor. When an approved existing phase needs a new comparison base, reconcile its verified ready plan with an explicit local or remote-tracking ref while keeping its phase branch fixed, then requalify an eligible reviewed predecessor with the user's genuine authority statement and a fresh full review. Use the physical branch name for the PR target (for example, `main` when the comparison ref is `origin/main`). Preserve authority text and history. The local CLI/MCP boundary records caller-provided text and does not independently authenticate actor identity.

Record review with `workflow_task_record_review`, checks and acceptance with `workflow_task_record_validation`, and approved local/commit/PR delivery with `workflow_task_deliver`. Use only returned current refs. Complete every acceptance obligation and independently read back canonical delivery. A changed snapshot needs full review and validation. Never claim unrun checks, hide findings, or bypass exhausted budgets. On ambiguous operations/jobs, inspect exact references and `status`/`result` before resuming the same operation; no blind new mutation.

For an authorized PR, use `workflow_task_watch_pr` as the sole event-driven watch. Persist each event disposition before acknowledging delivery; unresolved work stays visible. Continue eligible phases while the watch runs, then end the model turn when no action is ready. Outside established-watch maintenance, close out completed work with `workflow_task_finish`; then use `workflow_task_view` and its `complete` status and verified output references as the canonical mechanical readback. When semantic inspection of a stored output is required, request that listed output by key with `detail=packet` and judge the full returned body against task acceptance. Use typed validation/delivery results and the current snapshot for source binding; runtime checks receipt, head, tree, generation and revision. Do not write scripts or manually re-parse artifacts to repeat those mechanical checks. Keep handoff memories private and print only canonical URIs verified by readback.
